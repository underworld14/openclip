## User impact

A user who batch-exports with the "Reels (4:5)" platform preset gets clips whose burned karaoke captions are ~30% smaller linearly (44.5% of frame width instead of 63.2%) and sit ~25px higher off the bottom edge than the size they chose and than the live preview showed them — the preview overlay sizes captions off frame WIDTH while libass sizes them off PlayResY=1920, so preview and export disagree by 1.42x on 4:5. No warning, no error; the clips are usable but off-brand/small, and any per-project caption sizing tuned in the 9:16 preview is silently wrong for the 4:5 batch. If an aspect picker (1:1 / 16:9) is ever wired up — the schema, IPC validation, ffmpeg dimensions and the ExportPanel dimension table already support all four — the same defect becomes severe there (1:1 = 56% linear, 16:9 = 32% of intended share of frame width).

## Fix

Thread the real export canvas into the ASS builder and express Fontsize/margins in canvas-relative units so the burn matches the width-based preview.

1. src/main/services/ass-captions.ts — add `playRes?: { x: number; y: number }` (or `aspect: AspectRatio`) to `BuildAssOptions`; emit `PlayResX/PlayResY` from it (default stays `ASS_PLAY_RES` 1080x1920 so every existing 9:16 golden stays byte-identical). Since the styles are authored against a 1080-wide canvas and the preview scales by width (caption-css.ts:29-41), scale the style numbers by `k = playRes.x / 1080` inside `buildStyleLine`: `Fontsize = round(style.fontSize * k)`, MarginL/R `60*k`, MarginV `80*k`, and `Outline`/`Shadow` likewise. With `playRes = outputDimensions(aspect)` this makes k=1 for 9:16/4:5/1:1 (all 1080 wide) and k=1.78 for 16:9 — i.e. the caption keeps the same fraction of frame width at every aspect, which is what the preview already promises.
2. src/main/services/ffmpeg-caption.ts — add `aspectRatio: AspectRatio` to `WriteClipCaptionsOptions` and pass `playRes: outputDimensions(opts.aspectRatio)` through to `buildAss` (import `outputDimensions` from ./ffmpeg-export, or move it to a shared module to avoid the caption->export import).
3. src/main/services/jobs/export-runner.ts:219 — pass `aspectRatio: params.aspectRatio` in the `writeClipCaptions({...})` call (and widen the injected `deps.writeClipCaptions` signature at :65).
4. Update the frozen-ish header comments at ass-captions.ts:64-66 and :400-401 ("matches the 1080x1920 export canvas") and tests/unit/ass-captions.spec.ts:340-341 which asserts the hardcoded PlayRes.

## Regression test

Two tests, both red today.

(a) Unit — tests/unit/ass-captions.spec.ts: `buildAss({ words, clipStart: 0, clipEnd: 2, playRes: outputDimensions('1:1') })` must contain `PlayResY: 1080` and a `Style: Karaoke,...` line whose Fontsize is 64 and MarginV 80 (k=1 at 1080 width); and `outputDimensions('16:9')` must yield `PlayResX: 1920` with Fontsize 114 / MarginV 142. Today buildAss has no such option and always emits `PlayResY: 1920` + Fontsize 64, so the spec fails to compile/assert.

(b) Serial smoke — tests/unit/ass-captions.serial.spec.ts (`@serial`, skipIf no ffmpeg): write the clip .ass for '9:16' and for '1:1' via `writeClipCaptions`, burn each with `subtitles=` onto `color=black:s=1080x1920` and `color=black:s=1080x1080` respectively, then measure ink extents with `-vf format=gray,bbox=min_val=16` and assert the two glyph heights agree within 10%. Measured today: 48px vs 28px (0.58x) -> fails; after the fix both are ~48px. Same assertion for 4:5 (34px vs expected 48px) covers the actually-reachable batch-export regression.
