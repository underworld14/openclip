## Current behavior

ImportPanel.tsx:99 renders `{ctl.stage} · {ctl.pct}%` where stage is a lowercase internal token from import-pipeline.ts:54,59,72 ('probing' / 'extracting' / 'transcribing'). No elapsed time, no ETA, no file size. import-pipeline.ts:109 discards the byte counts the download runner computes: `onPartial: (data) => opts.onProgress?.(data.pct, 'downloading')`. On the export side, export-runner.ts:151 emits `progress(0, 'analyzing')` once and nothing further until encoding starts — for a reframe+silence clip that is an unbounded frozen 0% bar, and it is the slowest phase (up to four separate decodes of the span with no plan cache).

## Desired behavior

A named stage checklist rather than one bar: Import ✓ → Extract audio ✓ → Transcribe (live, 62%) → Find clips. Human labels, elapsed time per stage, byte counts and MB/s during downloads, and a realistic up-front estimate. Sub-progress during 'analyzing' (frames sampled / total) so it never sits at zero.

## Competitor precedent

OpusClip surfaces a named stage machine (IMPORT/CURATE/REFINE/RENDER/UPLOAD) plus an estimated wait. LokaClip shows a 6-stage strip (Unduh → Potong → Framing → Subtitle → Watermark → Finalisasi). YT-Short-Clipper uses horizontal numbered step cards with per-step bars and a green check on completion.

## Implementation sketch

New `components/StageProgress.tsx` fed by a `STAGE_LABELS` map ('probing'→'Reading video', 'extracting'→'Extracting audio', 'transcribing'→'Transcribing', 'analyzing'→'Analyzing faces & silence', 'encoding'→'Rendering'). Stop discarding bytes at import-pipeline.ts:109 — widen `onProgress` to `(pct, stage, detail?)`. In export-runner.ts, emit incremental progress from inside the reframe frame-sampler loop (reframe-detect.ts already streams rawvideo frames — count them against the known frame budget) so 'analyzing' moves. Track a `startedAt` per stage in the controller for elapsed display.
